# Daily Poem Feature

## Overview

A daily poem generated by Google Gemini AI, stored in your Neon PostgreSQL database, cached in Upstash Redis, and displayed on your homepage.

## Architecture

```
GitHub Actions (cron, daily)
  └─> POST /api/poems/generate
        └─> Gemini API (free tier)
        └─> Save to Neon DB (poems table)

Homepage (user visits)
  └─> <Poem /> Server Component
        └─> Read from Redis cache (fast path)
        └─> Fallback: read latest from Neon DB
        └─> Cache result in Redis for 24 hours
```

## Setup Steps

### 1. Get a Gemini API Key (free)

1. Go to [Google AI Studio](https://aistudio.google.com/app/apikey)
2. Create a new API key
3. Add it to your Vercel project as `GEMINI_API_KEY`
4. Also add it to your local `.env.local` for testing

### 2. Configure GitHub Actions

1. In your GitHub repository settings, add these secrets:
   - `API_URL` — your Vercel deployment URL (e.g., `https://your-portfolio.vercel.app`)

2. The workflow file `.github/workflows/generate-poem.yml` will automatically run daily at midnight UTC.

3. You can also trigger it manually via "Actions" > "Generate Daily Poem" > "Run workflow".

### 3. Configure Upstash Redis (caching layer)

1. Create a Redis database at [Upstash](https://upstash.com)
2. Add these environment variables to your Vercel project:
   - `UPSTASH_REDIS_REST_URL` — your Redis REST URL
   - `UPSTASH_REDIS_REST_TOKEN` — your Redis REST token

### 4. Verify

- Check your Vercel deployment has `GEMINI_API_KEY` and Redis env vars set
- Trigger the GitHub Actions workflow manually
- Check the logs to confirm a poem was generated
- Visit your homepage to see the poem

## API Endpoints

### `POST /api/poems/generate`

Generates a new poem using Gemini 3.5 Flash (Interactions API) and saves it to the database. The poem is a 2-3 stanza rhyming piece based on the developer's CV, referencing specific tech, metrics, and projects.

**Response:** `{ id: number, generatedAt: number }`

> **Note:** The `GET /api/poems/today` endpoint was removed. The homepage now uses a Server Component that reads directly from the database (with a Redis cache layer), eliminating the API route entirely.

## Database Schema

```sql
CREATE TABLE "poems" (
  "id" integer PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  "content" text NOT NULL,
  "generated_at" integer NOT NULL
);
```

## Free Tier Limits

- **Gemini 3.5 Flash**: rate-limited free tier (no credit card)
  - Uses the Gemini Interactions API for newer response format compatibility
- **GitHub Actions**: 500 build minutes/month (free for public repos)
- **Neon Postgres**: 512MB storage (free tier)
- **Upstash Redis**: 256MB storage (free tier)

A daily poem uses ~1 request per day, well within all limits.
